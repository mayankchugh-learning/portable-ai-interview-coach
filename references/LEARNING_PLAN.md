# Sustainable 15–30-minute daily training

## 15-minute session
1. 2 min — recall yesterday's single correction and one relevant memory anchor.
2. 1 min — receive ONE targeted question.
3. 3 min — user answers out loud; assistant waits until explicit `Finished`.
4. 4 min — DART diagnosis with a five-part /25 rubric, one technical correction.
5. 3 min — user retries only the problematic part, if desired.
6. 2 min — log score, correction, confidence and next prompt.

## 30-minute session
1. 3 min — quick review.
2. 10 min — first question and feedback.
3. 10 min — second question and feedback.
4. 5 min — one micro-redo and minimal rewrite.
5. 2 min — save handover and close.

## Topic rotation (flexible)
| Day | Focus |
|---|---|
| Mon | Enterprise/AI architecture, boundaries, API and data flows |
| Tue | Python, RAG retrieval, grounding, agents and testing |
| Wed | Cloud architecture, integration, Azure/AWS, reliability and incidents |
| Thu | Security/privacy, identity, authorisation, governance and risk |
| Fri | Educational or business evaluation, selection bias, KPIs and FinOps |
| Sat | Behavioural leadership, prioritisation, disagreement and communication |
| Sun | One mixed scenario or rest/recap |

Use **one question only** for shorter sessions. For an upcoming job description, replace rotation with relevant role requirements. Never force seven consecutive days or duplicate a missed session.

## 6-week outcome targets (not guarantees)
- Week 1: direct answer in first sentence, fewer filler/repeated words.
- Week 2: distinguish identity, access control, retrieval and generation layers.
- Week 3: failure isolation, observable SLOs, HTTP 429 and capacity boundaries.
- Week 4: pilot hypotheses, fair comparisons, causal limitations and user value.
- Week 5: manager decision, named owners, approvals and risk-based escalation.
- Week 6: role-specific 45–60-second answers, behavioural stories with true facts.

Re-evaluate priorities weekly based on the newest actual attempts, not calendar alone.
